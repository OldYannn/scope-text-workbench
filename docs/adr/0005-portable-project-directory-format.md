# ADR 0005：可迁移的项目目录格式

- 状态：Accepted
- 日期：2026-08-21
- 决策范围：Milestone 1A 项目持久化

## 背景

Milestone 1A 首次保存真实研究语料。项目格式既要让没有编程背景的研究者容易备份，也要为后续清洗、分析结果和研究记录预留稳定升级路径。该格式一旦被用户长期保存，就会形成兼容性约束。

## 决策

一个 SCOPE 项目就是一个普通文件夹。首版格式如下：

```text
项目名称/
├── project.json
├── scope.db
└── corpus/
    └── original/
        └── <document_id>.txt
```

- `project.json` 保存项目唯一标识、项目名称、创建时间、创建项目的软件版本和 `format_version`；
- `scope.db` 是项目自己的 SQLite 数据库，保存文档元数据、用于预览的原始文本和轻量研究审计记录；
- `corpus/original/` 保存导入文件的逐字节副本，文件名使用 `document_id`，不依赖原始文件所在位置；
- 原始来源路径只作为来源信息保存，重新打开项目时不会再次读取该位置；
- `input_hash` 是导入文件原始字节的 SHA-256。原始副本不做转码或修改，预览文本使用严格 UTF-8 解码；
- `format_version` 和 SQLite `user_version` 分别标识目录格式与数据库 Schema。未来版本在打开项目时按版本执行显式迁移；本轮遇到未知版本时拒绝打开，不静默改写。

项目目录可以整体移动、复制和备份。目录内部的相对位置必须保持不变。

## 为什么采用这个方案

普通目录容易理解，也可以直接使用操作系统和现有备份工具。SQLite 提供事务、唯一约束和后续查询能力；保存原始字节副本则保证来源证据不会因为外部原文件被移动或修改而丢失。与单一压缩包或自定义扩展名相比，这个方案在 Pre-alpha 阶段更容易检查和恢复。

## 暂不采用

- 单一 `.scope-project` 文件：需要提前锁定扩展名、压缩和写入恢复规则；
- 只保存原始路径：外部文件移动后项目不可复现；
- 只保存 JSON：长文本查询、唯一约束和后续迁移成本更高；
- 把语料放入全局应用数据库：项目无法整体迁移，也不利于隐私边界。

## 后果与风险

- 同一份文本同时保留原始字节副本和数据库预览文本，会增加存储占用；这是可复现性与简单读取换来的明确成本；
- 用户不应只移动 `scope.db`，而应移动整个项目文件夹；
- 后续版本必须维护迁移测试，任何破坏性格式变更仍需项目负责人批准；
- Pre-alpha 阶段暂不承诺自定义扩展名，未来如需封装格式，应另立 ADR。

## 项目负责人说明

对使用者来说，一个文件夹就是一个完整项目。把整个文件夹复制到移动硬盘或另一台电脑，就带走了项目身份、原始语料和软件记录。当前没有需要项目负责人立即选择的专有格式；长期风险主要是存储空间增加，以及未来版本必须认真维护升级兼容。
